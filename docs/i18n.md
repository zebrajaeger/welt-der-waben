# Translating the application

The app uses i18next with 30 complete bundled JSON catalogs in `src/locales/`. English (`en.json`) is the reference and fallback language. No translation server, external fonts or browser storage is needed.

At startup a supported manual selection stored under `carnivore-sim.language` wins. Otherwise the first supported entry in `navigator.languages` is used. Each entry is matched exactly, then by explicit or likely script, then base language, before trying the next preference. An absent or empty list uses `navigator.language`. Without a match English is used. Document language and number formatting use the selected catalog locale.

The globe button at the top right opens the language choices. Each choice shows its own language name and a flag, independent of the current UI language. Switching immediately updates text and numbers while preserving the running world, pause state, chart history/options and form draft. The selected language is saved separately from simulation settings. If browser storage is blocked, switching still works for the current visit. Open with Enter/Space, navigate with Tab or arrow keys, and close with Escape or an outside click.

The supplied package contains English (`en`), German (`de`), French (`fr`), Spanish (`es`), Italian (`it`), Portuguese (`pt`), Dutch (`nl`), Polish (`pl`), Czech (`cs`), Ukrainian (`uk`), Russian (`ru`), Turkish (`tr`), Greek (`el`), Romanian (`ro`), Hungarian (`hu`), Swedish (`sv`), Danish (`da`), Finnish (`fi`), Norwegian Bokmål (`nb`), Arabic (`ar`), Hebrew (`he`), Hindi (`hi`), Bengali (`bn`), simplified Chinese (`zh-Hans`), traditional Chinese (`zh-Hant`), Japanese (`ja`), Korean (`ko`), Indonesian (`id`), Vietnamese (`vi`) and Thai (`th`). Portuguese regional preferences share `pt`; flag regions are recognition aids, not separate regional translations.

Browser matching checks exact locale, explicit or likely script, then base language within each preference. Chinese `zh`/`zh-CN`/`zh-SG` maps to `zh-Hans`; `zh-TW`/`zh-HK`/`zh-MO` maps to `zh-Hant`. An explicit script overrides the region. Norwegian `no` maps to Bokmål (`nb`), while `nn` remains a separate, unsupported language. Each catalog carries `language.direction` (`ltr` or `rtl`).

To add a language:

1. Copy `en.json` to a BCP 47 filename, for example `fr.json` or `pt-BR.json`.
2. Translate the values, keeping keys and named `{{parameters}}` unchanged. Set `language.nativeName` to the language's own name, such as `Français`, and `language.direction` to `ltr` or `rtl`. Set `language.flag` to a local SVG basename in `src/flags/` (for example `fr` for `fr.svg`), or an empty string to use the globe fallback. Translate complete messages; do not assemble sentences from language-specific fragments. Keep Σ in energy sum labels. English fallback handles missing or empty translations at runtime, but shipped text entries must be complete.
3. Run `npm test -- tests/i18n.test.ts tests/catalog-check.test.ts tests/history-format.test.ts` and `npm run build`. Files are discovered automatically; no supported-language list or UI branch needs editing. Update the expected package in the catalog test when intentionally adding a language.
4. Select the language using the globe button (new catalogs appear automatically) and check controls, settings errors, history, tooltips and narrow windows. To test automatic browser detection again, remove only `carnivore-sim.language` from local storage and reload. Run `npm run test:production` for production browser checks.

To add a message, add a stable semantic key to English and all supplied catalogs, then call `i18n.t(key, parameters)`. Static HTML uses `data-i18n` for text-only nodes and `data-i18n-aria-label` / `data-i18n-title` for attributes. Its `__I18N:key__` placeholders are replaced by escaped English catalog text by Vite, then by the selected language at startup. Use text/attribute APIs rather than translated HTML.

Numbers use cached `Intl.NumberFormat` instances. Keep precision explicit: two decimals for current energy/time, one for the history X-axis, integer counts. Formatting is presentation only. Numeric inputs, settings JSON versions, parameter paths and saved simulation records do not contain translated values or language preferences. Language is stored under its own key.

Arabic explicitly uses the `arab` numbering system because Intl/CLDR versions have different defaults for bare `ar`. Hindi and Bengali retain their locale's Indian grouping. Bengali uses a conservative 75% character threshold before scientific notation because its fallback glyphs exceed the Latin zero width used by CSS `ch`; the reserved field size stays fixed. Full finite values remain accessible when scientific notation is needed. Canvas numeric labels keep physical right/left anchors and bounded widths.

Arabic and Hebrew set document `dir="rtl"`; all other supplied catalogs use `ltr`. Text labels follow that direction. Native names use `bdi`, mixed interpolation values use Unicode isolate boundaries in RTL sentences, and number/input/select slots use isolated LTR direction. The header grid and playback controls stay physically LTR, with the globe on the right; their text retains its language direction. The field and chart coordinates stay unchanged: counts on the left, energy on the right, time increasing to the right. Canvas labels set text direction explicitly. Changing language preserves nodes, draft, pause state and recorded samples.

Known errors carry a stable code, parameters and optionally a field path; only the UI translates them. Catalog tests compare keys and interpolation parameters and check English references. Regional catalogs are complete files too; missing or empty entries fall back through the base language to English at runtime, for example `de-CH` → `de` → `en`.

The language list is sorted by catalog code and scrolls inside the available viewport. Opening it focuses and reveals the selected language without scrolling the page. Home/End and arrow keys also reveal the focused option.

Run `node scripts/check-translations.mjs` (Node.js 22.18+ for native TypeScript stripping) to check catalogs and print identical English messages for review. `problems` must be empty. `reviewIdentical` is advisory: shared words, technical names such as JSON, and units can legitimately be identical. Review complete copied sentences and domain terms separately; passing structural checks does not establish translation quality.

The second content pass reviewed all new catalogs for population counts versus Σ-energy, simulation time versus playback speed, apply/restart versus save, complete error templates and file/storage notices. The reported identical entries are shared terms (Pause, Tick, Details, Series), species names in French, and `(max. 300 s)`. The French status sentence also has identical spelling because Tick, herbivores and carnivores are French terms; it was explicitly reviewed. Polish rate-label grammar and Arabic save-help wording were corrected. This is an authored translation and content review, not independent native-speaker certification in 28 languages.

`e2e/languages.pw.ts` selects every catalog and checks translated errors and persistence. `e2e/international-layout.pw.ts` covers RTL state preservation, stationary-pointer tooltips, cross-language JSON, blocked storage, local-only requests, and screenshots for ten representative languages at 1440 × 900, 360 × 740 and 360 × 480. Screenshot attachments are written under ignored `test-results/`; review the plot, language list, native glyphs and header geometry when changing catalogs or styles.

| Asset | Before expansion (en/de) | Thirty languages |

| JavaScript | 97.45 kB / 31.87 kB gzip | 328.67 kB / 90.42 kB gzip |
| CSS | 8.58 kB / 2.38 kB gzip | 9.25 kB / 2.56 kB gzip |
| HTML | 8.65 kB / 2.80 kB gzip | 8.65 kB / 2.80 kB gzip |

All catalogs and SVG flags are bundled eagerly to keep startup and switching synchronous. The additional compressed JavaScript is about 58.55 kB; no runtime translation requests or dependencies were added.

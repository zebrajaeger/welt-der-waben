# Translating the application

The app uses i18next with bundled JSON catalogs in `src/locales/`. English (`en.json`) is the reference and fallback language; German is supplied in `de.json`. No translation server or browser storage is needed.

At startup a supported manual selection stored under `carnivore-sim.language` wins. Otherwise the first supported entry in `navigator.languages` is used. Each entry is matched exactly, then by base language: `de-CH` → `de` → English if no preference matches. An absent or empty list uses `navigator.language`. Document language and number formatting use the selected catalog locale.

The globe button at the top right opens the language choices. Each choice shows its own language name and a flag, independent of the current UI language. Switching immediately updates text and numbers while preserving the running world, pause state, chart history/options and form draft. The selected language is saved separately from simulation settings. If browser storage is blocked, switching still works for the current visit. Open with Enter/Space, navigate with Tab or arrow keys, and close with Escape or an outside click.

To add a language:

1. Copy `en.json` to a BCP 47 filename, for example `fr.json` or `pt-BR.json`.
2. Translate the values, keeping keys and named `{{parameters}}` unchanged. Set `language.nativeName` to the language's own name, such as `Français`. Set `language.flag` to a local SVG basename in `src/flags/` (for example `fr` for `fr.svg`), or an empty string to use the globe fallback. Translate complete messages; do not assemble sentences from language-specific fragments. Keep Σ in energy sum labels. English fallback handles missing or empty translations at runtime, but shipped text entries must be complete.
3. Run `npm test -- tests/i18n.test.ts` and `npm run build`. Files are discovered automatically; no supported-language list or UI branch needs editing.
4. Select the language using the globe button (new catalogs appear automatically) and check controls, settings errors, history, tooltips and narrow windows. To test automatic browser detection again, remove only `carnivore-sim.language` from local storage and reload. Run `npm run test:production` for production browser checks.

To add a message, add a stable semantic key to English and all supplied catalogs, then call `i18n.t(key, parameters)`. Static HTML uses `data-i18n` for text-only nodes and `data-i18n-aria-label` / `data-i18n-title` for attributes. Its `__I18N:key__` placeholders are replaced by escaped English catalog text by Vite, then by the selected language at startup. Use text/attribute APIs rather than translated HTML.

Numbers use cached `Intl.NumberFormat` instances. Keep precision explicit: two decimals for current energy/time, one for the history X-axis, integer counts. Formatting is presentation only. Numeric inputs, settings JSON versions, parameter paths and saved simulation records do not contain translated values or language preferences. Language is stored under its own key.

Known errors carry a stable code, parameters and optionally a field path; only the UI translates them. Catalog tests compare keys and interpolation parameters and check English references. Regional catalogs are complete files too; missing or empty entries fall back through the base language to English at runtime, for example `de-CH` → `de` → `en`.
